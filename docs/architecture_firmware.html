02 · Ordonnancement

19 tâches, deux cœurs, trois priorités

Toutes les tâches sont créées par creerTacheSurveillee() (module système), qui appelle xTaskCreatePinnedToCore et garde la poignée pour mesurer la pile restante. Sur ESP-IDF, la taille de pile est en octets (StackType_t = uint8_t).

Pourquoi ces trois niveaux

Haute (3) : Modem et Mise a jour. Le lecteur d'URC doit vider l'UART avant les clients qui le polluent ; la tâche de mise à jour doit consommer sa file aussitôt, sinon la tâche BTC de Bluedroid reste bloquée dans xQueueSend (jusqu'à 3 s).

Normale (2) : ce qui réagit à un événement humain ou radio (SMS, appels, haut-parleur, bouton, caméra, réception de fichier). Un SMS entrant passe devant le sondage GPS.

Basse (1) : les boucles périodiques (GPS 1 s, réseau 10 s, batterie 5 s, LED 20 ms, journal, système, appli BLE). Même priorité que loopTask d'Arduino (supprimée à la fin du setup()), donc partage du temps par tranche de 1 ms entre elles.

Aucune n'est en temps réel dur : tout passe par vTaskDelay, xQueueReceive avec délai ou ulTaskNotifyTake. Aucune attente active, ce qui laisse tourner la tâche Idle du cœur 0, surveillée par le chien de garde des tâches (TWDT).

05 · Modem A7670E

Un seul fil, un seul propriétaire

L'UART1 (115200 8N1, tampon de réception 4 Ko) est lu et écrit uniquement par module_modem.cpp. Les clients appellent envoyerCommandeAT(), qui prend le verrou récursif, vide les URC en attente, écrit, puis lit ligne par ligne jusqu'à OK/ERROR/+CME ERROR/+CMS ERROR, en distribuant au passage les URC qui arrivent au milieu.

Anatomie d'une transaction AT

prendreLeModem(délai + 5000)        // xSemaphoreTakeRecursive
traiterLesLignesEnAttente()          // URC déjà arrivées → abonnés
print("AT+CGNSSINFO\r")
boucle lireUneLigne(20 ms)
  ""  ou écho                    → ignorée
  "OK" / "ERROR" / "+CME ERROR"  → fin
  préfixe abonné ("+CMTI:"…)     → rappel, continue
  sinon                          → ajoutée à *reponse
rendreLeModem()

Pourquoi récursif

Le module SMS prend le verrou une fois pour toute la séquence CSCS="GSM" → CSMP → CMGS → CSCS="UCS2", puis chaque envoyerCommandeAT() à l'intérieur le reprend. Personne ne peut changer le jeu de caractères entre deux lignes.

Pourquoi vider avant d'écrire

Une URC arrivée entre deux commandes serait sinon lue comme première ligne de la réponse suivante (par exemple RING pris pour le résultat de AT+CSQ).

Envoi avec données

envoyerCommandeATAvecDonnees() attend l'invite > (sans fin de ligne) caractère par caractère pendant 5 s, écrit le binaire, puis Ctrl-Z (SMS) ou rien (AT+CFTRANRX, taille annoncée). Sans invite : Échap pour annuler la saisie côté modem.

06 · Bluetooth Low Energy

Un service, huit caractéristiques, tout chiffré

Pile Bluedroid (bibliothèque BLEDevice d'Arduino), nom Moto_ESP32, MTU demandé 517, puissance +18 dBm (annonce, balayage et liaisons). Toutes les caractéristiques et leurs descripteurs CCCD exigent ESP_GATT_PERM_*_ENC_MITM : sans appairage par code PIN, rien n'est lisible ni inscriptible.

UUIDNomProp.Rappel / émetteur

Sécurité

ESP_LE_AUTH_REQ_SC_MITM_BOND : LE Secure Connections (ECDH P-256), protection MITM par code fixe SECRET_BLE_PIN (dans secrets.h, jamais publié), clé de liaison stockée en NVS (bonding).

onConfirmPIN renvoie false : pas de comparaison numérique, le module n'a pas d'écran. Échec d'authentification → disconnect().

Double garde : la permission GATT refuse l'accès non chiffré, et chaque onWrite vérifie aussi telephoneAuthentifie.

Écarté

Just Works (aucune protection MITM, n'importe qui à 30 m pilote les SMS et appels) ; un mot de passe applicatif dans le protocole (en clair sans chiffrement de lien).

Débit et contre-pression

Vers le téléphone : notifier() est sérialisé par verrouDesNotifications et marque une pause de 8 ms après chaque notification. Sans pause, une rafale (état complet, page de dossier) remplissait les tampons du contrôleur et Android coupait. Plafond théorique ≈ 125 notifications/s, soit ≈ 60 Ko/s à 509 octets.

Téléchargement : fenêtre de 8 morceaux, puis attente de DL_ACK <octets> (5 s max). Contrôle de flux applicatif, car une notification n'a pas d'accusé.

Vers le module (OTA, fichier entrant) : écriture avec réponse. Le rappel bloque la tâche BTC dans xQueueSend quand la file est pleine, les écritures suivantes ne sont plus traitées, le téléphone ralentit de lui-même.

Taille utile : min(MTU − 3, 500). Un JSON plus long est refusé (journal série), d'où la liste des tâches en paquets de 5 et les pages de dossier de 380 octets.

Le principe

La RAM interne est réservée à ce qui doit être rapide ou accessible quand le cache flash est coupé (piles, files de petits messages, Bluedroid, DMA SDMMC). Les gros tampons tolérants à la latence partent en PSRAM. Une file en PSRAM se crée avec xQueueCreateStatic et un stockage heap_caps_malloc(MALLOC_CAP_SPIRAM), car xQueueCreate alloue en interne.
